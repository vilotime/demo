# 快速开始

## 1. 写文档

在仓库根目录的 `md/` 下新建任意层级的文件夹和 `.md` 文件：

```text
md/
├── index.md
├── 指南/
│   ├── 01-快速开始.md        ← 本文件
│   ├── 02-目录与文件规范.md
│   └── 进阶/
│       └── 03-Markdown 语法速查.md
└── 示例/
    └── 01-演示模式示例.md
```

文件名前面加上 `01-` `02-` 这样的数字前缀，目录树和「上一篇 / 下一篇」就会按这个顺序排列。站点不会因为你没有写前缀而乱序——默认用的是「自然排序」，`第2章` 会排在 `第10章` 前面。

## 2. 本地预览

```bash
# 在仓库根目录
node tools/dev-server.mjs        # 或 npm run dev
```

打开终端里打印出来的地址（默认 <http://127.0.0.1:5173/>）。不需要任何构建命令：这个本地服务器每次请求目录索引时都会现场扫描 `md/`，所以新增文件后**刷新页面**即可看到，也不会在仓库里留下构建产物。

> 直接双击 `index.html` 用 `file://` 打开是不行的：浏览器安全策略不允许页面用 `fetch`
> 读取本地 `.md` 文件。请务必通过本地服务器预览。

## 3. 部署到 GitHub Pages

部署全部交给 GitHub Actions，本地不用构建、也不用提交任何生成物：

1. 打开仓库 **Settings → Pages**；
2. 把 **Source** 选成 **GitHub Actions**；
3. 之后每次 push 到 `main` 分支，`.github/workflows/pages.yml` 都会自动扫描 `md/`、生成目录索引并发布。

> 目录索引 `md-index.json` 不放进仓库（已在 `.gitignore` 里排除），
> 由 CI 在部署时生成。因此不要用「Deploy from a branch」方式发布，
> 那条路径不会生成索引，页面读不到目录树。

## 站点相对路径的设计

站点的所有资源都用**相对路径**（`assets/...`、`md/...`），没有写死 `/xxx`。所以它既能部署在 `https://<用户名>.github.io/`，也能部署在`https://<用户名>.github.io/<仓库名>/` 这样的子路径下，不需要改任何配置。

## 常用快捷键

| 快捷键 | 作用 |
| --- | --- |
| `/` | 聚焦左侧搜索框 |
| `Ctrl/⌘ + Enter` | 在阅读模式 / 演示模式之间切换 |
| `j` / `k` | 下一篇 / 上一篇文档 |
| `Esc` | 关闭搜索、退出演示 |
| `o` | （演示模式）幻灯片总览 |
| `f` | （演示模式）全屏 |
