# MD Pages

把仓库根目录的 `md/` 文件夹变成一个**纯静态**的文档站点：

- 📁 左侧像文件资源管理器一样按目录层级列出所有 `.md` 文件（支持多层嵌套、折叠、搜索）；
- 📖 **阅读模式**：渲染 Markdown，右侧大纲跟随滚动，底部上一篇 / 下一篇；
- 🎬 **演示模式**：把同一篇 Markdown 按分页规则切成 16:9 幻灯片，支持键盘翻页、缩略图总览、全屏；
- 🚀 部署到 GitHub Pages：所有资源都用相对路径，放在根域名或子路径下都能跑。

线上效果取决于你的内容，把 `md/` 里的示例文件换成自己的即可。

---

## 目录结构

```text
.
├── index.html                  站点外壳（唯一页面，靠 hash 路由切换文档）
├── md/                         ★ 你的 Markdown 文档放这里（可任意嵌套）
│   ├── index.md                首页（存在时会自动打开）
│   ├── 指南/
│   │   ├── 01-快速开始.md
│   │   ├── 02-目录与文件规范.md
│   │   └── 进阶/
│   │       └── 03-Markdown 语法速查.md
│   └── 示例/
│       ├── 01-演示模式示例.md
│       ├── 02-阅读模式示例.md
│       └── 附件/示意图.svg     文档引用的图片，就近存放
├── assets/
│   ├── css/site.css            全部样式（含深浅主题、打印样式）
│   ├── js/markdown.js          Markdown 渲染管线（marked + 扩展 + 分页切分）
│   ├── js/presenter.js         演示模式引擎（自适应切页 / 翻页 / 总览）
│   ├── js/app.js               目录树、路由、阅读模式、交互
│   ├── vendor/marked.min.js    本地内置的解析器（不依赖 CDN，离线也能用）
│   ├── vendor/highlight.min.js 代码高亮
│   └── favicon.svg
├── tools/
│   ├── build-index.mjs         扫描 md/ → 目录索引（部署时由 Actions 调用）
│   ├── dev-server.mjs          本地预览服务器（现场生成索引，不落盘）
│   ├── smoke-test.mjs          渲染 / 分页 / 路径解析 单元测试
│   ├── dom-test.mjs            用 jsdom 跑的端到端交互测试（可选）
│   ├── audit.mjs               CSS / HTML / JS 静态体检（可选）
│   └── inspect-slides.mjs      查看某篇文档实际会切成哪几页（调试用）
├── .github/workflows/pages.yml 推送到 main 后生成索引并发布
└── .nojekyll                   告诉 GitHub Pages 不要用 Jekyll 处理
```

仓库里**没有构建产物**：`md-index.json`（目录索引）只在部署时由 Actions 生成，
本地预览在内存里生成、不写文件，所以它也不会出现在你的工作区里。

## 本地预览

```bash
node tools/dev-server.mjs      # 或 npm run dev
# → http://127.0.0.1:5173/
```

> ⚠️ 不要直接双击 `index.html`。浏览器安全策略禁止 `file://` 页面用 `fetch`
> 读取同目录的 `.md` 文件，必须通过本地服务器访问。

不需要任何构建命令：服务器每次收到索引请求都会现场扫描 `md/`，
所以**新增 / 改名文件后刷新页面就能看到**。

## 写文档

1. 在 `md/` 下新建文件夹和 `.md` 文件，层级随意嵌套；
2. 想要固定顺序就用数字前缀：`01-`、`02-`……（站点使用自然排序，`第2章` 会排在 `第10章` 前）；
3. 文档标题就是正文的第一个一级标题（第一行写 `# 标题`），目录树、面包屑、演示模式封面都用它；
   没有一级标题时退回文件名；
4. 图片、PDF 等附件就近放在文档旁边，用相对路径引用即可（`![图](./附件/图.svg)`）。

文档里**只需要写正文**：不需要标题字段、日期、作者之类的前置信息，
站点也不会读取任何写在正文之外的内容。

## 演示模式怎么分页

进入方式：右上角「演示」按钮 / `Ctrl(⌘) + Enter` / 直接访问带 `?mode=ppt` 的链接。

按优先级：

1. 正文的第一个一级标题所在的那一页自动排成封面；
2. 独立成行的 `---`、`***`、`___`，或显式的 `<!-- slide -->` 注释 → 分页；
   （代码块里的这些符号不会被误判）
3. 全文都没有分页符时，退化为按 `##` 二级标题分页（没有二级标题则按 `#`）；
4. 单页放不下时，先尝试整体缩小字号，再在段落 / 列表 / 代码块之间**自动续页**，
   所以超长文档也不会溢出画面。

分页间隔里可以放 `slide=页码` 深链接，刷新后仍停在原页。

## 快捷键

| 快捷键 | 作用 |
| --- | --- |
| `/` | 聚焦左侧搜索框 |
| `Ctrl/⌘ + Enter` | 阅读模式 ⇄ 演示模式 |
| `j` / `k` | 下一篇 / 上一篇文档 |
| `→` `↓` `Space` `PageDown` | （演示）下一页 |
| `←` `↑` `PageUp` | （演示）上一页 |
| `Home` / `End` | （演示）首页 / 末页 |
| `o` / `Esc` | （演示）缩略图总览 |
| `f` | （演示）全屏 |
| `q` | （演示）退出演示 |

## 部署到 GitHub Pages

部署全靠 GitHub Actions，**本地不需要构建、也不需要提交任何产物**：

1. 把整个项目推到 GitHub；
2. 仓库 **Settings → Pages → Source** 选择 **GitHub Actions**；
3. 之后每次 push 到 `main`，`.github/workflows/pages.yml` 会依次：
   checkout → 用 `node tools/build-index.mjs` 生成目录索引 → 打包整个目录 → 发布。

仓库名随便起，部署在 `https://<用户名>.github.io/<仓库>/` 子路径下也能正常工作，
因为站点里没有任何写死的绝对路径。

> 因为索引不提交到仓库，**不要**用「Deploy from a branch」这种方式发布，
> 那条路径不会生成 `md-index.json`，页面会读不到目录树。

### 为什么要 md-index.json

GitHub Pages 只有静态文件，浏览器无法"列出某个目录下有哪些文件"。
所以目录树必须在部署时扫描成一份清单，页面启动时读取它——这件事在 CI 里做完了，
你只管提交 `.md`。

## 自定义

| 想改什么 | 改哪里 |
| --- | --- |
| 配色 / 圆角 / 行宽 | `assets/css/site.css` 顶部的 `:root` 与两个主题块 |
| 侧边栏宽度、大纲宽度 | `--sidebar-w`、`--toc-w` |
| 幻灯片画布尺寸 | `presenter.js` 里的 `SLIDE_W` / `SLIDE_H`（改比例需同步 CSS） |
| 站点标题 | `index.html` 里的 `.brand__text` |
| Markdown 扩展 | `assets/js/markdown.js` 的 marked 实例 |

## 测试

```bash
npm test                 # 纯 Node，无需安装依赖：渲染 / 分页 / 路径解析

npm install              # 下面两条依赖开发依赖（jsdom、css-tree）
npm run audit            # CSS 语法、CSS 变量、HTML id / JS 引用一致性
npm run test:dom         # 端到端交互测试（需先启动 dev-server）
```

## 说明与边界

- 内容按你自己的文档渲染，Markdown 里的原始 HTML 会原样保留（站点是给你自己用的，不做 XSS 过滤）；
- 没有服务端，所以没有全文搜索索引，搜索只匹配当前目录树里的文件名 / 标题 / 路径；
- 目录索引由 CI 在部署时生成，改完文档 push 上去就生效，本地不用跑任何构建命令。
